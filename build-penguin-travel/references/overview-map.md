# 目的地手绘行程总览

## 风格与范围
参考 [Travel-Plan-Page](https://github.com/do-tongxue/Travel-Plan-Page) 的纸感、低饱和山水地形、城市建筑线稿、弯曲路线和交通图标；只借鉴视觉语言，不采用它的固定虚构地形底图或每日地图规则。本模板总览展示城市之间的移动，每日地图继续展示实际街道点位。

## 生成步骤
1. 阅读整趟旅行的城市、往返顺序和交通方式，核实各城市相对方位及所在地的海岸、河流、山地、岛屿或平原特征。根据行程地理跨度选择地区/多地区画布；跨国或远距离旅行可分区，但不要把城市硬摆在错误的国家、海上或山中。
2. 为本次目的地生成专属4:3手绘背景：米白纸纹、轻水彩地形、细手绘线稿、少量当地典型建筑或植被。保留真实地区的主要形态与相对方位，不照搬任意固定岛屿、山林或海岸。不要求精确地图比例，标注“手绘路线示意”。跨区域的压缩尺度需明确分区且不颠倒方向。
3. 优先生图能力；无生图能力则制作原创SVG手绘底图，依据核实的地理信息，不用通用圆点流程图替代最终手绘地图。底图不画城市文字、路线、编号、日期、交通图标或图例；这些由代码叠加，便于复用。
4. 保存到项目assets/，在overview设置mapImage和canvas（默认960×720）。为每座城市设置position=[x,y]，是底图画布0–1的归一化位置，必须和背景中实际城市位置对齐。北在上、东在右；不能根据访问顺序交替左右排列。如果分区/画面有不同投影，逐区核对标注。
5. 保留cities的稳定ID、名字、停留D几–D几，legs的from/to/mode/status。可记录已核实的coordinates=[lat,lon]供核对；labelOffset=[dx,dy]为画布单位、labelAnchor为start/middle/end，用于避让长名称。不要移动节点以掩盖错位，不将缺坐标的备用布局称为地理地图。
6. 使用模板的弯曲路线、编号点、飞机/巴士等图标叠加，往返线分开、箭头朝实际目的地。名称使用深色与浅色描边保证清晰，底图不随每日日期切换。过多城市时扩大/分区画布或调整标签，不丢中转/返程信息。
7. 手机与桌面实际查看，检查背景、地形、城市、天数、交通与待确认状态。底图文件失败时保留城市/路线文字和提示，不能留下无限加载。

## 生图提示模板
> 为【旅行地区】绘制4:3横向手绘地图背景，地形依据【已核实的海岸/山地/河流/岛屿/平原特点】，北上东右，符合【城市列表】的真实相对方位。米白纸张纹理、低饱和水彩、细手绘轮廓、少量当地建筑和植被，地图区域与城市标注空间清晰。只画地理背景，不含名称、文字、数字、线路、交通标记、logo或水印。用于网页叠加旅行路线，并非精确比例导航地图。

## 示例与回退
随附assets/overview-map.svg明确是虚构港湾山地示例，只用于展示风格。实际目的地必须换底图与position，不可只改城市名。旧资料没有mapImage/position时仍可显示路线示意及待完善提示；这种回退不是完成的目的地地图。
