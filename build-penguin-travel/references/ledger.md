# 记账：固定布局、计算与验收

## 页面与操作
- 将记账放在长网页最后一个主区域，其他主区域一直保留。内部仅切换“记账 / 账单结算”。设置图标在这两个入口旁，禁止全局设置。
- 记账视图依次为：录入表单、账单笔数及时间排序、账单列表。“我的旅行花费”显示在账单列表头部；禁止个人支出加团队总支出的“总支出”指标。
- 录入字段为金额、币种、分类、日期、付款人、分摊人员、备注和可选照片；可平分或自定义分摊，提供全选参与人。编辑复用录入表单，保存后更新列表和结算。
- 每笔展示原币金额、必要的折算金额、日期、分类、付款人及参与人。允许编辑、删除、单独改备注、查看照片；删除须确认。列表按账单时间可切换升降序，账单笔数随增删更新。
- 结算视图依次显示“我的总支出”（本位币合计及本人各原币支出）、“我的分类支出”（仅本位币）和原有结算方案。两种支出统计只计本人承担，代垫他人部分不计入；未选本人提示选择，无支出显示空状态，有支出币种/分类才列出。分类按相同币种加权汇率计算，累计后用最大余数分配展示分钱尾差使分类合计等于本人总额，不改变本人承担或转账算法。原币明细只作总额的分解，不能重复加总。按付款人→收款人组合展示转账建议，每组列出各原币种金额，多币种或非本位币时再显示约合本位币。不得仅显示折算总数；无需额外增加每人收支卡或所有人收支大表。无账单显示添加提示，已有账单且无转账显示已结清。
- 设置弹窗按人员与本人、本位币与常用币种、统一汇率分组；支持人员添加/改名/删除，姓名生成头像文字、颜色可改；成员管理返回设置后保留状态。已有账单关联的人员不可直接删除。本人保存稳定 ID，未选择时提示，改名不改变身份，不预设原作者姓名。
- 有账单后锁定本位币；每笔保存当时汇率与折算值，仅修改设置不会改动已保存账单。新建或通过完整账单表单重新保存时使用当前设置汇率、重算折算值；编辑保存前显示将使用的汇率。单独编辑备注/照片保留汇率。汇率表达为“1 原币 = X 本位币”。
- 手机端人员头像小巧、选择区易点，金额/笔数统一 sans-serif 与 tabular-nums。设置固定头部和关闭入口、可滚动内容与可达保存区，输入字号至少16px；不得撑宽页面。
- 数据同步使用每位使用者的独立服务。默认无账单导出/导入功能。

## 固定计算顺序
保存原币最小单位整数、币种、付款人 ID、参与人 ID、分摊模式、保存汇率、本位币折算值；自定义份额以本位币最小单位记录，合计必须等于账单已保存折算值。

按原币币种分组，组内以高精度累加，不逐笔四舍五入人均：
1. 累加原币总额和各付款人的原币付款额；累加各笔原币金额乘保存汇率的精确本位币值。
2. 平分账单按该笔参与人数形成精确份额。不同参与集合分别计算后累加，不能把全组总额直接除以全部同行人数。自定义账单按各人的自定义本位币份额占该笔折算总额的比例分配原币金额。
3. 该币种有效汇率 = 全组精确折算合计 / 原币总额。不同保存汇率用金额加权，不能使用当前设置或汇率简单平均。
4. 本人及各人的承担额 = 每个币种中其原币精确份额 × 该组有效汇率，再跨币种累加，最后四舍五入到本位币最小单位。
5. 各人的付款额使用其每笔金额与保存汇率的精确折算累加后舍入；应收为付款减承担，应付为承担减付款。“我的旅行花费”直接复用承担结果，不能另算。
6. 各币种先用“原币付款 − 原币精确承担”生成原币转账；按债务/债权大小匹配，稳定 ID 打破同额排序。每笔转账用组有效汇率折算，按付款人→收款人分组保留各币种原币转账，并累加约合本位币用于辅助显示；各显示金额最后舍入。录入只接受正额账单；零额、负数与无效金额拒绝保存，不能进入有效汇率除法。

区分存储金额与计算精度；不同币种先换算至原币金额单位再乘汇率，不能默认所有币种都有两位小数。

## 舍入边界
按本位币最小单位显示（CNY到分）；采用各人的累计结果独立四舍五入，不把0.01尾差强行分配给某个人，也不强制个人显示合计等于总账显示合计。UI 简短注明这项规则。
转账的付款方与收款方使用同一笔建议金额，保证转账两端一致；原币精确净余额及匹配结果必须守恒。允许显示舍入导致的分钱差异，不得用全局尾差调整悄悄改变本人承担算法。

## 必做算例（仅虚构数据）
- A本人个人100 CNY；A/B/C共同300 CNY；A替B垫付200 CNY且A不参与：A的旅行花费200，付款600，折算净额400，转账建议收回400；B承担300，C承担100；B→A300，C→A100。
- A付款两笔各1 THB，A/B/C平分，汇率0.2：先合计2 THB，人均2/3 THB，A的旅行花费0.13 CNY；不得逐笔舍入成0.14。B与C各转A0.13，两端金额一致；独立舍入有0.01差异，不强补。
- A付款100 THB汇率0.2，B付款100 THB汇率0.3，两人均参与：组汇率0.25，各承担25 CNY；付款A20、B30。仅将设置汇率改为0.4，已有账单未重新保存时承担仍为25；原币双方净额均为零，转账建议为空，不按折算净额产生5 CNY转账。
- A付款90 CNY由A/B平分、60 CNY由B/C平分：承担A45、B75、C30，不能全组150除以3。
- A付款100 CNY，自定义A30/B70：本人A花费30，B→A70。自定义合计99须拒绝保存。
- 未选择本人时显示提示；改名保留 ID 和计算；编辑金额/参与人、删除账单后花费/笔数/转账一起重算；照片与备注修改不改变金额。
- 用对应币种精度验证零额、负数、NaN、无参与人、重复参与人、未知人员、非正汇率；错误必须阻止保存并明确提示。

## 统计与转账口径
折算付款减承担仅为统计净额，不是转账算法。不同保存汇率时它可能与原币结算不同；转账以第6步原币净额为准，不以第5步净额另生成转账或新增应收应付卡。
改变汇率设置本身不改变保存数据；同币种新账单加入或旧账单重新保存会重新计算该币种加权汇率，因此不能承诺历史个人承担贡献永远不变。
对原币及本位币按币种精度处理，CNY算例中的 cents 指分，不可把 JPY/KWD 都强行设为两位。自定义分摊和校验也使用本位币最小单位。
