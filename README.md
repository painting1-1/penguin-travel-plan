<h1 align="center">跟小企鹅一起出发吧 🐧</h1>

把航班、酒店、想去的地方和旅行需求交给 AI，套用一张适合手机查看的旅行网页。

**仓库现在包含可运行网页模板和配套 Skill。** 布局、地图、清单、攻略和记账交互已经做好；AI 主要整理并替换你的旅行资料，核对地点和时间，再为这趟旅行换一张封面。下一次出发，也可以继续用同一套模板。

## 页面里有什么

默认是一张连续长网页。顶部「行程／行李／必买／待办／记账」导航滚动到对应区域，其他板块一直保留。

| 板块 | 功能 |
| --- | --- |
| 标题与封面 | 旅行标题、日期、天数、目的地封面 |
| 此刻关注 | 下一件重要事项的倒计时，到点后切换下一项 |
| 行程总览 | 城市之间的交通方向、方式和旅行阶段 |
| 已经确认的安排 | 分段航班、中转、酒店房型及取消期限；待购票／待预约另列 |
| 每日行程 | 日期切换、时间线、转场和夜宿，活动前有当日地图与全天导航 |
| 行李清单 | 分类折叠、按组勾选、分类及整体准备进度，刷新保留 |
| 必买榜单 | 添加名称和可选图片，图片预览内上传／换图／移除，商品可删除 |
| 待办 | AI 从旅行资料整理办理时间和期限，部分事项可下载日历提醒 |
| 旅行记账 | 多人多币种、平分／自定义分摊、本人花费、账单编辑与人员结算 |

地点名称直接打开地图，旁边的 ⓘ 展开一段简介；活动标题右侧的 📕＋ 保存小红书链接或分享口令，可修改和移除。「有空再逛」可折叠。

设置只在记账里，管理同行人、本人、币种与汇率。「我的旅行花费」只计本人承担的份额，替别人垫付不算自己的消费；转账建议按人员组合列出各原币金额，并显示约合本位币。

行李内容由 AI 整理，网页只勾选；待办也是展示型提醒，不在网页内编辑、删除或完成勾选。改行程时由 AI 更新待办和顺序。

## 先看看模板

1. 点击 **Code → Download ZIP**，解压仓库。
2. 安装 Python 3，在仓库目录运行：

```bash
python3 -m http.server 8000
```

3. 浏览器打开 **http://localhost:8000/**。

如果已经有 Node.js，也可以运行：

```bash
npm run preview
```

预览不需要 `npm install`。Windows 若使用 `python` 命令，请将上述 `python3` 换成 `python`。

不要直接双击 `index.html`；页面通过本地 HTTP 读取 `trip-data.json`。示例行程、人员、航班和地图点位均为虚构，不可拿来实际出行。地图底图和外部导航／攻略需要网络。

## 让 AI 换成你的旅行

### 会安装 Skill

保留完整的 `build-penguin-travel` 文件夹，按 AI 工具提供的方式安装或导入，再调用 `build-penguin-travel`。不能只复制 `SKILL.md`，完整模板、图标和参考规则也需要一起保留。

### 不会安装，也能用

把完整仓库提供给能读取文件、运行代码的 AI，然后复制这段话：

> 请使用这个仓库的「跟小企鹅一起出发吧」模板，先阅读 build-penguin-travel/SKILL.md 及其引用规则。复用现有网页代码，主要修改 trip-data.json 和本次旅行封面，不重新设计布局、按钮或记账功能。我的目的地是【】，日期是【】，同行【】人，已确定的航班和酒店是【】，想去的地方是【】。请为新旅行生成独立 trip ID，核实地图点位、交通时间和确认状态，从资料整理待办；运行验证和测试，自查手机端后给我可用预览。公开部署前向我确认。

修改同一趟旅行可以说：

> 在第二天下午增加一站咖啡店，先给方案。我确认后同步更新时间、地图、导航和待办，保留这趟旅行的 ID、已有账单、攻略和行李勾选。

支持 Skill 的工具之间安装和调用方式不同；模板可直接预览，资料核对与部署由 AI 配合你的环境完成。

## 下一次旅行怎么复用

Skill 的素材准备脚本会复制完整网页，并为新旅行生成独立存储编号：

```bash
python3 build-penguin-travel/scripts/scaffold.py --output my-next-trip
```

已有整理好的资料也可以传入：

```bash
python3 build-penguin-travel/scripts/scaffold.py --output my-next-trip --data my-trip.json
```

输出必须是新目录或空目录。指定资料时保留该资料的 `id`：新旅行请用新 ID，同一趟旅行更新保留旧 ID。然后修改 `trip-data.json`，在新目录预览即可。

网页代码与旅行资料分离，日期、城市、天数和每日行程都由资料驱动，支持不同目的地与天数。封面可替换为本次地标背景，主屏幕图标继续使用小企鹅。

## 关于地图

**行程总览**展示城市间移动；**当日地图**展示全部停靠点、编号和游览顺序，保留返回酒店等往返路线。

当日地图默认采用 OpenStreetMap，保留署名。地点名称和全天路线打开外部地图导航；示意线不冒充实际道路轨迹。点位未核实就标为区域示意或待补充，底图失败时仍可查看地点和导航。

## 数据保存与分享

默认是 **当前浏览器本地保存**，包含行李勾选、购物、攻略和账本。不同旅行用独立 ID 隔离；清除浏览器数据可能丢失，换设备不会自动同步。多标签页发生写入冲突时提示刷新，避免覆盖另一个页面的修改。

`trip-data.json` 是旅行计划和首次使用的初始资料，已有账单和购物数据保存在浏览器里。改 JSON 不会覆盖这些记录；已有账本的人员和币种请在记账设置修改。

需要多人／多设备同步时，由 AI 为你配置独立存储并测试。需要私密访问时使用服务端验证；模板默认没有登录保护，也不内置公共数据库或作者后台。

想分享网页，可部署到自己的静态托管服务，例如 Cloudflare Pages。部署和公开分享需要你的明确授权；发布前清除订单号、证件号、密码和开发密钥。

## 验证与测试

需要 Python 3 和 Node.js，在仓库目录运行：

```bash
python3 scripts/validate_trip.py trip-data.json
npm test
```

验证工具检查日期、时区、稳定 ID、地图点位引用和人员关联；测试覆盖本人花费、多人分摊、汇率汇总、原币结算和不同币种精度。资料结构通过不代表营业时间、坐标或交通预算已核实，AI 仍需完成旅行事实检查和手机交互自查。

## 项目结构

```text
index.html / styles.css / template.css    网页与手机布局
app.js / ledger.js / storage.js           行程、记账与本地保存
trip-data.json                           每趟旅行的资料
assets/cover.svg                         可替换的封面
icons/ / site.webmanifest                小企鹅主屏幕图标
vendor/                                  随附地图组件
scripts/ / tests/                        预览、验证与测试
build-penguin-travel/                    完整可安装 Skill
```

Skill 文件夹内也包含同一份可运行模板，安装后无需访问原作者私人网站或下载其他底板。

## 关于这个项目

模板来自一张逐步完善的个人旅行网页，希望其他人也能直接套用，也方便自己每次出发继续使用。

参考项目：[Travel-Plan-Page](https://github.com/do-tongxue/Travel-Plan-Page)。部分通用旅行组件经个人网页调整后用于此模板，许可说明见 [THIRD_PARTY_NOTICES.md](THIRD_PARTY_NOTICES.md)。

本仓库不包含原作者的真实同行人、私人行程、酒店订单、账单、邮箱、密码和数据库配置。
